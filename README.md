# Крок 01 — базова HTML-структура

Гілка: `step-01-base-html`

На цьому кроці ти створиш лише каркас сторінки та переконаєшся, що браузер
правильно завантажує HTML, CSS і JavaScript. Поведінки тренажера ще не буде — це
навмисне обмеження.

## 1. Мета гілки

Після виконання кроку ти зможеш:

- пояснити базову структуру HTML5-документа;
- вибрати семантичний тег за призначенням вмісту;
- підключити зовнішні CSS- і JavaScript-файли;
- пояснити, навіщо скрипту атрибут `defer`;
- знайти елемент у панелі Elements;
- перевірити завантаження ресурсів у Network;
- розрізняти HTML-помилку, помилку завантаження і JavaScript-помилку.

## 2. Git-команди

Репозиторій поки не має комітів. Спочатку збережи навчальну основу в `main`:

```powershell
git status
git add AGENTS.md README.md docs
git diff --cached
git commit -m "docs: add typing trainer course roadmap"
```

Перед `commit` уважно переглянь `git diff --cached`: у staged-змінах мають бути
лише навчальні Markdown-файли.

Після початкового коміту створи навчальну гілку:

```powershell
git switch -c step-01-base-html
git status
```

Очікування: останній рядок першої команди повідомляє про перехід на нову гілку,
а `git status` показує `On branch step-01-base-html`.

Якщо твоя версія Git не підтримує `switch`, допустимий старіший варіант:

```powershell
git checkout -b step-01-base-html
```

Не виконуй обидві команди створення гілки.

## 3. Що потрібно зробити

### Крок 1. Створи три порожні робочі файли

У корені проєкту створи:

- `index.html` — структура й зміст сторінки;
- `style.css` — майбутнє оформлення;
- `app.js` — майбутня поведінка.

Поки не додавай CSS і JavaScript. Порожні файли потрібні, щоб відразу перевірити
правильність шляхів підключення.

Після створення виконай:

```powershell
git status --short
```

Ти маєш побачити три нові untracked-файли з позначкою `??`.

### Крок 2. Додай декларацію HTML5 і кореневий елемент

Почни `index.html` із декларації типу документа. Після неї створи кореневий
елемент `html` і встанови мову українського вмісту.

Подумай над двома питаннями:

- Чому декларація типу документа не є звичайним HTML-тегом?
- Як правильний `lang` допомагає браузеру й екранному читачу?

Перевірка: відкрий файл у браузері, а потім у DevTools виконай в Console:

```text
document.documentElement.lang
```

Очікуваний результат — код української мови `uk`.

### Крок 3. Побудуй `head`

Усередині `head` послідовно додай:

1. Кодування UTF-8.
2. Налаштування viewport для мобільних екранів.
3. Зрозумілий заголовок вкладки.
4. Підключення `style.css` відносним шляхом.
5. Підключення `app.js` зовнішнім тегом `script` з атрибутом `defer`.

Не копіюй готовий блок. Для кожного елемента знайди відповідь: яку проблему він
розв'язує і що станеться, якщо його прибрати.

Чому `defer`: браузер може завантажувати зовнішній скрипт паралельно з розбором
HTML, але виконає його після побудови документа. На майбутніх кроках це дозволить
JavaScript безпечно знаходити елементи сторінки.

Перевірка:

- на вкладці браузера видно задану назву;
- українські символи відображаються без спотворень;
- у Network після перезавантаження є `index.html`, `style.css` і `app.js`;
- для всіх трьох ресурсів немає статусу `404`.

Підказка: відкрий DevTools до перезавантаження сторінки, перейди в Network і
увімкни фільтр `All`.

### Крок 4. Створи семантичний `body`

Розділи сторінку на три верхньорівневі частини:

- `header` — назва застосунку й короткий опис;
- `main` — єдиний основний вміст поточної сторінки;
- `footer` — короткий навчальний підпис або інформація про проєкт.

У `header` додай один головний заголовок сторінки та коротке пояснення її
призначення. На сторінці цього кроку має бути лише один `h1`.

У `main` створи окрему секцію тренажера. Секція повинна мати власний заголовок,
щоб її призначення було зрозумілим і без візуального оформлення.

Чому так: семантичні теги описують роль вмісту, а не його зовнішній вигляд. Це
полегшує навігацію допоміжними технологіями й робить структуру зрозумілішою для
розробника.

### Крок 5. Підготуй елементи майбутнього тренажера

Усередині секції додай:

1. Блок майбутньої статистики з трьома текстовими показниками: час, WPM і
   точність. Значення поки можуть бути початковими, наприклад нульовими.
2. Контейнер для еталонного тексту з коротким статичним реченням українською.
3. Поле для введення тексту з видимим підписом `label`.
4. Кнопку скидання з текстом, який описує дію.

Вимоги до поля:

- `label` пов'язаний із полем через пару `for`/`id`;
- є підказка, що саме потрібно вводити;
- не використовуй `placeholder` як єдиний підпис;
- якщо обираєш `textarea`, будь готовий пояснити його перевагу над однорядковим
  `input` для набору довших текстів.

Вимоги до кнопки:

- використовуй справжній елемент `button`, а не стилізовані `div` чи `a`;
- явно задай безпечний тип кнопки, враховуючи можливе майбутнє розміщення у
  формі;
- на цьому етапі кнопка може нічого не робити.

Не додавай обробники подій, таймер або підрахунки. Це належить наступним гілкам.

### Крок 6. Перевір структуру без CSS

Відкрий панель Elements і перевір дерево документа:

- `header`, `main` і `footer` є сусідами всередині `body`;
- секція тренажера знаходиться в `main`;
- заголовки мають логічну ієрархію без пропущеного рівня;
- `label` і поле мають узгоджені `for` та `id`;
- немає елементів, доданих лише заради майбутнього кольору чи відступу.

Сторінка виглядатиме просто. Це правильний результат: зараз перевіряється
структура, а не дизайн.

### Крок 7. Перевір підключення JavaScript

Тимчасово додай до `app.js` один діагностичний виклик `console.log` із коротким
повідомленням про завантаження застосунку. Перезавантаж сторінку та знайди це
повідомлення в Console.

Після успішної перевірки можеш залишити повідомлення до наступного кроку або
видалити його. Не додавай іншої логіки.

Так ти доведеш, що шлях до файлу й момент виконання скрипту налаштовані правильно.
Якщо повідомлення не з'явилося:

1. Перевір Console на помилки.
2. Перевір точне ім'я файла й регістр символів.
3. Перевір шлях у `src`.
4. Перевір Network на `404`.
5. Переконайся, що Console не має активного текстового фільтра.

### Крок 8. Перевір зміни через Git

Виконай:

```powershell
git status --short
git diff --check
git diff
```

`git diff --check` не повинен показати помилок зайвих пробілів. У `git diff`
самостійно перевір:

- чи немає випадково доданих секретів або локальних шляхів;
- чи всі теги закриті;
- чи немає CSS або функціональності з майбутніх кроків;
- чи назви й текст зрозумілі без додаткового пояснення.

Поки не роби commit із реалізацією: спочатку пройди Definition of Done і попроси
рев'ю.

## 4. Критерії готовності — Definition of Done

Крок готовий до рев'ю, якщо всі твердження правдиві:

- [ ] Поточна Git-гілка — `step-01-base-html`.
- [ ] У корені є `index.html`, `style.css` і `app.js`.
- [ ] Документ використовує HTML5, UTF-8, українську мову та mobile viewport.
- [ ] Назва вкладки описує тренажер.
- [ ] CSS і JavaScript підключені як зовнішні файли відносними шляхами.
- [ ] Скрипт має `defer`.
- [ ] Є семантичні `header`, `main`, `section` і `footer`.
- [ ] На сторінці один `h1`, а ієрархія заголовків логічна.
- [ ] Є області для часу, WPM, Accuracy, еталонного тексту та Reset.
- [ ] Поле введення має видимий і програмно пов'язаний `label`.
- [ ] Кнопка є елементом `button` із явно заданим типом.
- [ ] У Console немає червоних помилок.
- [ ] У Network немає `404` для локальних файлів.
- [ ] `document.documentElement.lang` повертає `uk`.
- [ ] Сторінкою можна пройти клавішею Tab до поля й кнопки.
- [ ] `git diff --check` завершується без повідомлень.

Для рев'ю надішли ментору:

```powershell
git status --short --branch
git diff --check
```

А також опиши:

- що побачив у Console;
- чи всі три файли завантажилися без `404`;
- яке значення повернув `document.documentElement.lang`.

## 5. Питання для самоперевірки

1. Чим семантичний елемент `main` відрізняється від звичайного `div` і скільки
   основних `main` має бути на сторінці?
2. Чому зовнішній скрипт у цьому проєкті підключається з `defer` і чим це
   відрізняється від розміщення `script` у кінці `body`?
3. Чому `placeholder` не замінює `label`, і як атрибути `for` та `id` утворюють
   зв'язок між підписом і полем?
